## What this is

A multi-tenant MCP server that scrapes a student's ManageBac account and exposes it to
ChatGPT (Apps SDK) and Claude. Python + httpx + BeautifulSoup + Starlette/uvicorn.
Students enroll at `https://managebac.822538.xyz/enroll` and receive a private connector
URL. Per-request user identity is carried via `contextvars` (`set_current_user` /
`require_user`). Admin manages all users at `https://managebac.822538.xyz/admin`.

**Tools (14):** `get_classes, get_timetable, refresh, get_upcoming, get_tasks,
get_task_detail, get_files, get_journal, get_file_content, get_units, get_grades,
tag_search, find_task, test_ui`

## Multi-user architecture

Every HTTP request to `/mcp` extracts the user's secret key from `?key=…`, looks up the
user in `users.db`, sets them as current user via `contextvars`, then calls into the MCP
server. Each user has isolated session cookies, cache, and token.

**Users DB columns:** `id, token, label, mb_url, mb_email, mb_password_enc,
session_cookies, created_at, enabled, approved, note`

`get_user_by_token()` — requires `enabled = 1` (active users only)
`get_user_by_token_any()` — returns paused users too; used by the MCP handler so paused
users reach `call_tool` and see the suspension prompt instead of a bare 401.

## Enroll flow

Two paths to enrollment:

**1. Web form** (`GET/POST /enroll`)
Student visits `https://managebac.822538.xyz/enroll`, fills in school URL + email +
password + invite code. Server verifies credentials against ManageBac live, creates the
user, returns a connector URL.

**2. In-chat** (`/connect` via `enroll_server.py`)
ChatGPT calls the `enroll` tool with school URL, email, and invite code (NO password).
Server creates a pending enrollment, returns a one-time secure link. Student opens the
link and enters their password there. Password never passes through the chat.

**URL normalization (both paths):** `_normalize_mb_url()` uses `urlparse` to strip any
path or query string — students can paste the full login URL
(`https://es.managebac.com/login`) and it resolves to `https://es.managebac.com`.

**Invite codes** are one-time 8-char hex codes generated by the admin. Each enrollment
consumes one code (atomic UPDATE … WHERE used_by IS NULL).

## Admin panel (`/admin`)

Single-page app (vanilla JS, no framework). Token stored in `localStorage`. All API
calls go to `/admin/*` with `Authorization: Bearer <token>`.

### Pages
| Page | What it does |
|---|---|
| Users | List all students, search/filter, stats cards (total/active/paused/health) |
| User → Profile | Account details, resource usage, View password, Edit email, Reset password (with live verify), Copy connector link, Pause/Resume, Send targeted message, Delete |
| User → Activity | Per-user tool call history |
| User → Cache | Per-user cache entries with individual Expire + Expire all |
| Server Health | Uptime, memory, CPU, total requests, avg response, active cache |
| Tool Call Logs | Cross-user tool call log (all users, newest first) |

### Sidebar nav bug
The nav buttons use `onclick="showView('name')"`. If a Chrome permission dialog (e.g.
clipboard) is overlaying the page, clicks on the sidebar can be swallowed. Workaround:
dismiss any browser permission bars first, or call `showView('name')` from DevTools.

## Admin → student intercepts

Both fire at the top of `call_tool()` in `server.py`, before any scraping:

### Pause intercept
If `is_enabled(user_id)` returns False, all tool calls return:
```
📢 Notice from your administrator: Your ManageBac account has been suspended...
```
With `isError=True` (bypasses ChatGPT's ManageBac widget renderer).

### Message injection
If `pop_message(user_id)` returns a message, that tool call returns the message instead
of its normal result:
```
📢 Message from your administrator:
{message}
```
With `isError=True`. Targeted messages are deleted on delivery. Broadcasts use a
`read_by` comma-list so each user sees each broadcast exactly once.

### ChatGPT display behaviour
`isError=True` bypasses the ManageBac widget. ChatGPT's reasoning model (o4) reads the
text and relays it. The prompts use plain text with no `[AI INSTRUCTION]` blocks —
instruction-tagged suffixes caused ChatGPT to classify the whole response as system
overhead and suppress the content.

## Widgets (ChatGPT Apps SDK)

> **Full reference: [`WIDGETS.md`](WIDGETS.md)** — registration, all `window.openai` APIs,
> display modes, CSP, interactivity patterns, gaps vs the docs, submission checklist.

Widget HTML lives in `widget-preview/`. Registered in `_STATIC_WIDGETS` in `server.py`
with `ui://widget/...-v2.html` URIs. A tool shows a widget when both its `Tool(_meta=…)`
and `CallToolResult(_meta=…)` point at the same URI and `structuredContent` carries the
data. The widget reads `window.openai.toolOutput`; the model reads the text content.

**Size limit:** Keep `structuredContent` under ~4–5 KB — ChatGPT silently drops anything
larger and falls back to plain text (no widget, no error). Slim with short keys.

**Cache bust:** To force a widget update in ChatGPT, bump the URI version suffix
(`-v2` → `-v3`). Users must also remove + re-add the connector in ChatGPT settings.

**Preview locally:** `.claude/launch.json` serves `widget-preview/` on `:8899`.

### Known gaps (not done yet)
- No `notifyIntrinsicHeight()` — widgets may clip at wrong height
- No dark mode — broken in dark ChatGPT
- `window.open()` used instead of `window.openai.openExternal()` — may be sandboxed
- No `outputSchema` on any tool — ChatGPT warns on every call (issue #24)
- CSP `resourceDomains` likely incomplete — cause of domain errors (issue #25)
- Widgets never request fullscreen — timetable/task list would benefit from it
- No `callTool` from any widget — tapping items is dead
- No `setWidgetState` — tab/filter position resets on every render

## Scraper gotchas (don't regress)

- **Real Chrome UA required.** ManageBac serves a reduced page to bot UAs (Files page
  missing folders). `auth.get_client()` sends a Chrome UA.
- **`data-ec3-info` double-escaping.** `parse_files` slices to outer `{…}` + collapses
  `\\`; uploader from `<label>by NAME</label>`; `uploaded_at` UTC → school-local.
- **Files paginate + nest in folders.** `fetch_files` BFS-crawls `/files/page/N` and
  recurses into `/files/folder/{id}`, tagging each file with `folder`.
- **`get_upcoming` empty is correct** at year-end.
- **Timetable `task_count`** is ManageBac's per-day badge, NOT a to-do count.
- **`get_timetable`** accepts `days` / `from` / `to` (natural language + dates), resolved
  school-local via `_filter_timetable`.
